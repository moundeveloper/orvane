## Notes and canvas

- [x] **Copy an image from Notes.** The owner cannot right-click a Notes image and copy the image itself. The context menu should offer **Copy image**, and the clipboard should contain image data usable by another app.
- [x] **Drag a Notes image onto the canvas.** The owner reported this twice together with the copy issue. Dragging an image block out of Notes onto empty canvas should place the image at the drop position. Verify that the Notes image remains intact and canvas zoom/pan are accounted for.
- [x] **Create a sticky note immediately at the pointer.** Add a shortcut that opens a focused sticky note at the current cursor position. Let the owner save it into a chosen existing Notes page or create a standalone Notes page. Verify that both destinations preserve the text.
- [x] **Restore caret position when deleting a to-do.** After deletion the caret appears at the ghost `TO-DO` placeholder instead of the start of the line. Cover an empty to-do and the transition from typed text to an empty line. Placeholder text must remain purely visual.
- [x] **Support Ctrl+X in Notes.** The owner says it does not cut the line of whichever box the caret is in. Verify selected text cutting and the current-line behavior with no selection, including the resulting clipboard, caret and stored content.
- [x] **Let Ctrl+Q work when Notes is focused.** Notes currently intercepts it. Preserve the established workspace shortcut from editable and non-editable Notes targets.
- [x] **Allow multiline captions on Notes images.** Captions on pasted images cannot go to the next line. Verify longer captions wrap and explicit line breaks survive editing and reopening.

## NetSuite Login window after reopening from the tray

- [x] **Recheck the actual tray lifecycle.** The owner reported the same standalone dark `NetSuite Login` window after clicking Orvane's Close button and reopening it from the tray. The new screenshot shows the workspace restored behind the popup, with the embedded Browser sign-in page and active processing tabs in the workspace. The earlier startup-popup check did not exercise this sequence.
- Reproduced with a Windows Electron fixture using a real Browser webview, a real processing tab, and a native Browser selector that opens a second, nested `NetSuite Login` window. On the previous code, clicking **Close Orvane** and triggering the real tray click handler restored the workspace with the nested `NetSuite Login` window still visible. The processing-only fixture passed on the previous code and retained the same live WebContents across both cycles.
- Root cause in the reproduction was that `browserPopups` registered only windows opened directly by a webview. Native children opened by those dialogs skipped the tray lifecycle. `electron/main.mjs` now tracks the whole Browser popup chain, minimizes it when the workspace goes to the tray and before reopening a hidden workspace, and blocks popup creation from a minimized Browser dialog or while the workspace is hidden. Existing dialogs keep their instances for deliberate restoration. Processing tabs use their existing background path.
- `desktop-window.spec.ts` now passes two close-to-tray and reopen cycles with the nested login dialog and the same still-running processing tab. It also verifies that the minimized selector cannot open another window in the tray or immediately after reopening. Its existing window restore and drag test passed. The Browser desktop regression, type checking, and CSS checks passed. Verification used an isolated Electron profile. The owner's running Orvane process requires **Quit Orvane** from the tray menu and a fresh launch to load the main-process change.
- `netsuite-auto-login.spec.ts` also passed after the tray fix, covering NetSuite sign-in and background processing with the local HTTPS fixture.
